# M3/M4 Ingestion API

The M3/M4 gateway exposes a small versioned HTTP boundary. The API version is
`/v1`; it is separate from the canonical trace schema version
`agentlens-trace-v1`. The gateway accepts complete canonical `Trace` snapshots,
not independent span or event uploads.

## Authentication and authorization

Send a development API key as a Bearer token:

```text
Authorization: Bearer dev-m3-key-not-real
```

Keys resolve to safe `key_id`, `project_id`, and `enabled` metadata. The
development authenticator stores SHA-256 key digests and compares digests in
constant time. Raw keys are not logged or returned. A trace's `project_id`
must match the authenticated project's ID.

## Ingestion endpoints

### `POST /v1/traces`

Accepts one `agentlens-trace-v1` JSON document with `Content-Type:
application/json`. The gateway bounds the actual request body, authenticates
before canonical reconstruction, calls `Trace.from_dict`, checks project
ownership, and sends the canonical object to the sink.

New and identical duplicate submissions return `202 Accepted`:

```json
{
  "request_id": "server-generated-uuid",
  "trace_id": "trace-uuid",
  "status": "accepted",
  "duplicate": false
}
```

`duplicate` is `true` for an identical retry. Identity is
`(project_id, trace_id)` and changed content for an existing identity returns
`409 Conflict` without overwriting the original.

### `POST /v1/traces/batch`

Accepts `{"traces": [{...}, {...}]}`. The default maximum is 100 traces and
is configurable. An empty batch is rejected with `400 invalid_batch`. All
traces are parsed, reconstructed, authorized, and checked for repeated IDs
before the in-memory sink mutates. A malformed or unauthorized item rejects
the whole request. Repeated `trace_id` values in one batch return
`400 duplicate_trace_id`; existing identity conflicts return `409`.

Successful batches return `202` with `accepted_count`, `duplicate_count`, and
the ordered `trace_ids`.

### `GET /health/live`

Returns `200 {"status":"ok"}` when the HTTP process is serving requests.

### `GET /health/ready`

Returns `200 {"status":"ok"}` when configured components and the database are
ready. With a database-backed repository, it runs a cheap connectivity check;
database failure returns `503 {"status":"unavailable"}`. Liveness remains
database-independent.

## Errors and limits

Errors use this shape and always include the generated request ID:

```json
{
  "error": {
    "code": "invalid_trace",
    "message": "Trace payload is invalid.",
    "request_id": "server-generated-uuid"
  }
}
```

Implemented machine-readable codes are:

| Code | Status | Meaning |
| --- | ---: | --- |
| `invalid_json` | 400 | Body is not JSON |
| `invalid_request` | 400 | Framework-level request error |
| `invalid_batch` | 400 | Missing/empty batch envelope |
| `duplicate_trace_id` | 400 | Repeated ID in one batch |
| `unauthorized` | 401 | Missing, invalid, or disabled key |
| `project_forbidden` | 403 | Trace belongs to another project |
| `trace_conflict` | 409 | Same identity, changed canonical content |
| `unsupported_media_type` | 415 | Content type is not JSON |
| `invalid_trace` | 422 | M1 canonical reconstruction failed |
| `unsupported_schema` | 422 | Schema version is unsupported |
| `payload_too_large` | 413 | Actual body exceeds configured bound |
| `batch_too_large` | 413 | Batch exceeds configured trace count |
| `rate_limited` | 429 | Per-key process-local limit exceeded |
| `ingestion_unavailable` | 503 | Sink could not accept the trace |
| `internal_error` | 500 | Unexpected gateway failure |

The default body bound is 2 MiB. The rate limiter is a fixed-window,
process-local per-key limiter and returns `Retry-After` on `429`. The gateway
does not rely only on `Content-Length`; it bounds bytes actually read. Request
compression is not implemented in M3.

## Example

Use a clearly fake development key and a canonical trace generated by the SDK:

```python
from agentlens import AgentLens, HttpTraceExporter

exporter = HttpTraceExporter(
    base_url="http://localhost:8000",
    api_key="dev-m3-key-not-real",
)
client = AgentLens(project_id="support-agent", exporter=exporter)

with client.trace("request") as trace:
    with trace.span("work", span_type="custom"):
        pass
```

The local gateway must have the matching development key registered. With a
`DatabaseConfig`, M6 persists accepted traces, evaluation jobs, and immutable
evaluation results in PostgreSQL. The authentication registry remains
process-local. See [TRACE_QUERY_API.md](TRACE_QUERY_API.md) for trace
detail/list endpoints, [EVALUATION_RUNTIME.md](EVALUATION_RUNTIME.md) for
project-scoped job/result APIs, and
[DETERMINISTIC_EVALUATION.md](DETERMINISTIC_EVALUATION.md) for metric
semantics.
